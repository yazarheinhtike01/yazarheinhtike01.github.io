🗄️ Database Design — ဘာကြောင့် ဒီလိုခွဲထားလဲ
users — Login အတွက်၊ password ကို hash နဲ့သိမ်း၊ role ခွဲထား
students — ကျောင်းသားအချက်အလက်
attendance — ရက်အလိုက် မှတ်တမ်း၊ student_id နဲ့ Foreign Key ချိတ်
grades — ဘာသာအလိုက် အမှတ်
Table တွေကို တစ်ခုတည်းမှာ စုမထားဘဲ ခွဲထားတာက data ထပ်တာကို လျှော့ပြီး (normalization) ပြင်ရလွယ်အောင်ပါ။

    

  


  
  

    
Architecture — System တစ်ခုလုံး ဘယ်လိုအလုပ်လုပ်လဲ

    

      
1 · FrontendHTML / CSS / JavaScript
Form စစ်၊ Search, Table ပြင်။ Browser ထဲမှာ run တယ်။

      
2 · Java BackendService + DAO Layer
Login စစ် (Authentication)၊ ခွင့်ပြုချက် စစ် (Authorization)၊ Business logic။

      
3 · JDBCPreparedStatement
SQL Injection ကာကွယ်ဖို့ ? placeholder သုံးတယ်။ String ပေါင်းပြီး SQL မရေးဘူး။

      
4 · MySQLDatabase
users / students / attendance / grades tables။

    

    

      
Authentication vs Authorization
Authentication = သင်ဘယ်သူလဲ? — Username + Password စစ်ပြီး Login ဝင်စေတာ။
Authorization = သင်ဘာလုပ်ခွင့်ရှိလဲ? — Admin က Delete လုပ်နိုင်တယ်၊ Student က ကိုယ့်အချက်အလက်ပဲ ကြည့်နိုင်တယ်။
Demo မှာ Role ပြောင်းကြည့်ရင် ဒီကွာခြားချက်ကို လက်တွေ့ မြင်ရပါမယ်။

      
Login Flow (အင်တာဗျူးမှာ ရှင်းပြရန်)
  1. User က form မှာ email/password ဖြည့်
  2. Frontend က လွတ်နေတာ / ပုံစံမှားတာ အရင်စစ်
  3. Java AuthService က DB ထဲက hash နဲ့ တိုက်
  4. မှန်ရင် Session ထုတ်၊ Role အလိုက် screen ပြ
  5. မှားရင် generic error ပဲပြ — ဘယ်အပိုင်းမှားလဲ မပြော (security)

ဒီ Project ကနေ သင်ယူခဲ့ရတာ
• Layer ခွဲထားတာ (Model / DAO / Service) က code ကို ပြင်ရလွယ်စေတယ်
• PreparedStatement မသုံးရင် SQL Injection အန္တရာယ် ရှိတယ်
• Password ကို plain text မသိမ်းရဘူး — hash လုပ်ရတယ်
• Error ဖြစ်ရင် user ကို နားလည်လွယ်တဲ့ message ပြဖို့ လိုတယ်
